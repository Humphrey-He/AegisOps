# NebulaOps 前端功能清单与项目排期

> 项目名：NebulaOps  
> 前端技术路线：React + TypeScript + Vite + Ant Design/Semi Design + TanStack Query  
> 目标：构建成熟稳定、可长期维护、适合企业级运维操作的前端控制台。

## 1. 前端建设原则

NebulaOps 前端不是展示型后台，而是高风险运维操作入口。前端设计必须围绕“清晰、可控、可确认、可追踪”展开。

核心原则：

- 第一屏是工作台，不做营销页。
- 所有高危操作必须二次确认。
- 所有长耗时操作进入任务中心。
- 所有远程连接、发布、reload、删除都要展示实时状态。
- 所有资源页面必须支持搜索、筛选、分页、状态展示。
- 所有表单必须有前端校验和后端错误映射。
- 权限不足时隐藏入口，并对直接访问展示 403。
- 页面状态必须可恢复，刷新不丢关键任务。
- 前后端类型通过 OpenAPI 生成，减少接口漂移。

## 2. 推荐前端技术栈

```text
React + TypeScript + Vite + React Router + TanStack Query + Zustand + Ant Design
```

## 4. 页面功能清单

功能：

- 错误信息明确，不泄露敏感细节。
- 表单校验完整。

## 6. 前端状态与接口规范

### 6.1 状态分层

- TanStack Query：接口数据、缓存、轮询、重新请求
- Zustand：登录用户、菜单、主题、全局 UI 状态
- URL Query：列表搜索、筛选、分页
- Local State：表单临时状态、弹窗状态

### 6.2 API 约定

统一响应：

```ts
type ApiResponse<T> = {
  code: string;
  message: string;
  data: T;
  traceId: string;
};
```

前端处理：

- 401：跳转登录或刷新 Token
- 403：提示无权限，路由页显示 403
- 409：资源冲突，展示冲突原因
- 422：表单校验错误，映射到字段
- 500：展示 traceId，便于排查

## 8. 前端验收口径

### MVP 验收

- 用户可登录并进入工作台。
- 菜单根据权限展示。
- 可管理用户、角色、主机、凭证。
- 可打开 WebSSH 并稳定交互。
- 可管理 Docker 节点和 Registry。
- 可创建服务并提交发布任务。
- 可查看任务进度和日志。
- 可查看审计日志。
- 高危操作都有确认。

### V1.0 验收

- 支持服务升级、回滚和发布历史。
- 支持 Nginx 配置编辑、diff、test、reload、rollback。
- 支持 Jenkins Job 同步和触发构建。
- 表单错误能映射到字段。
- 刷新页面不丢任务状态。
- 主要流程有 Playwright E2E 覆盖。
- 适配 1366x768、1440x900、1920x1080 常见桌面分辨率。

## 9. 成熟落地建议

前端第一版不要追求炫酷视觉，而要追求稳定、清晰、低误操作。NebulaOps 的用户是在操作主机、容器、Nginx、Jenkins 这些高风险资源，真正的体验优势来自明确的状态、可靠的反馈、足够强的确认机制和可追踪的任务流。

最优先打磨 4 个交互闭环：

1. WebSSH 连接闭环：打开、连接、交互、断开、清理。
2. 服务发布闭环：配置、校验、提交、任务、结果。
3. Nginx 配置闭环：编辑、diff、test、reload、回滚。
4. 高危操作闭环：权限、确认、执行、审计、任务结果。

只要这 4 个闭环扎实，NebulaOps 的前端体验就会明显强于传统静态后台式运维面板。
