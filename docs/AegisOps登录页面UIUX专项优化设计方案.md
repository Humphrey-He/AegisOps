# AegisOps 登录页面 UI/UX 专项优化设计方案

## 1. 文档定位

本文档针对 AegisOps 当前登录页面进行专项 UI/UX 评审与优化设计，目标是把登录页从“可用的登录表单”升级为“可信、专业、有信息承载能力的企业级控制台入口”。

本方案面向前端开发、UI/UX 设计、产品验收和后续视觉改版落地使用。

## 2. 当前页面判断

当前登录页具备基础可用性：

- 登录卡片居中，视觉干净
- 表单字段简单，路径清晰
- 主按钮明确
- 文案能够说明登录后的基本去向

但从企业级产品入口体验看，页面仍显得偏“脚手架化”：

- 页面周边没有品牌信息、产品定位或安全信号
- 大面积浅灰背景未被利用，视觉重心过于单薄
- 登录卡片像独立组件，而不是完整产品入口
- 初始化管理员入口只是提示文字，缺少明确动作
- 没有环境标识、版本信息、部署状态等企业系统常见辅助信息
- 缺少对目标用户的信任建立，例如审计、权限、任务追踪、安全接入等能力提示

一句话概括：

> 当前登录页“能用”，但还没有承担企业级系统入口应有的品牌、信任、安全和引导职责。

## 3. 优化目标

### 3.1 企业化

登录页应体现 AegisOps 是一个稳定、可信、面向运维管理场景的企业级控制台，而不是一个普通后台模板。

### 3.2 专业化

页面应让用户在登录前就理解系统能力边界：

- 资产管理
- 运维执行
- 任务追踪
- 告警闭环
- 操作审计
- 权限控制

### 3.3 易用性

登录路径不能被装饰信息干扰。所有周边信息都应服务于判断和信任，而不是抢走表单焦点。

### 3.4 可落地

方案应优先复用当前 Ant Design、全局 token 和已有样式，不引入复杂动画或大规模视觉资产。

## 4. 推荐页面结构

建议将登录页从单卡片居中改为“左右分区式企业入口”。

### 4.1 桌面端布局

推荐布局：

- 左侧：品牌与产品信息区
- 右侧：登录表单区
- 底部：版本、环境、版权、部署信息

建议比例：

- 左侧信息区：52%
- 右侧表单区：48%
- 登录卡片宽度：420 到 460
- 页面最大内容宽度：1120 到 1200

文本线框示意：

```text
┌──────────────────────────────────────────────────────────────┐
│ AegisOps                                  Demo / Production  │
│                                                              │
│ ┌──────────────────────────────┐  ┌───────────────────────┐ │
│ │ 企业级运维控制台              │  │ 登录 AegisOps          │ │
│ │ 统一管理资产、任务、告警、审计 │  │ 用户名                 │ │
│ │                              │  │ 密码                   │ │
│ │ [资产接入] [任务追踪] [审计]  │  │ 登录控制台             │ │
│ │                              │  │ 初始化管理员 / 忘记密码 │ │
│ │ 系统状态：API 已连接          │  └───────────────────────┘ │
│ └──────────────────────────────┘                              │
│                                                              │
│ v0.4.0 · 内部运维系统 · 安全审计已启用                         │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 移动端布局

移动端不建议保留复杂左右布局。

推荐：

- 顶部显示品牌与一句定位
- 中间显示登录卡片
- 登录卡片下方显示初始化入口
- 能力标签和系统状态压缩为横向或换行标签
- 底部版本信息保留

## 5. 信息内容设计

### 5.1 品牌区

建议展示：

- AegisOps
- 企业级运维控制台
- 一句价值描述

推荐文案：

> 统一管理资产接入、任务执行、告警响应与操作审计，让运维动作有上下文、有记录、可追踪。

视觉建议：

- 品牌名称使用 28 到 36px
- 副标题使用 14 到 16px
- 不使用营销化大标题
- 不使用夸张渐变或装饰插画

### 5.2 能力标签区

用于填补周边空白，同时建立产品专业感。

建议标签：

- 资产接入
- 任务追踪
- 告警闭环
- 操作审计
- 权限控制
- 终端接入

展示方式：

- 使用轻量 Tag 或小型信息块
- 每项可配简短说明
- 不要做成大卡片堆叠

推荐内容：

| 能力 | 说明 |
| --- | --- |
| 资产接入 | 管理主机、Docker、Nginx 等运行资源 |
| 任务追踪 | 所有执行动作进入任务链路 |
| 告警闭环 | 异常事件可确认、处理和回溯 |
| 操作审计 | 关键操作形成可追溯记录 |

### 5.3 系统状态区

登录页适合展示少量系统状态，增强可信度。

建议展示：

- 当前环境：Demo / Production
- 数据源状态：Mock 数据源 / API 已连接
- 版本号：例如 v0.4.0
- 安全提示：审计已启用 / RBAC 已启用

注意：

- 不展示敏感后端地址
- 不展示 token、数据库、服务器内部信息
- 状态只是辅助信息，不应喧宾夺主

### 5.4 登录卡片

登录卡片仍然是页面主焦点。

建议保留：

- 标题：登录 AegisOps
- 用户名
- 密码
- 登录按钮

建议增强：

- 输入框前缀图标：用户、锁
- 密码可见切换保持默认
- 登录按钮文案保持 `登录控制台`
- loading 状态清晰
- 错误信息优先落在表单字段或卡片内，而不只依赖 message

推荐登录卡片结构：

```text
登录 AegisOps
使用管理员或授权账号进入控制台

用户名
[ user icon ] admin

密码
[ lock icon ] ********

[ 登录控制台 ]

尚未初始化？初始化系统管理员
```

### 5.5 初始化入口

当前初始化提示只是文本，不够明确。

建议改为明确操作：

- `初始化系统管理员`
- 作为文本按钮或次按钮
- 只在系统未初始化时重点显示
- 系统已初始化时弱化或隐藏

推荐文案：

> 首次部署 AegisOps？请先初始化系统管理员。

按钮：

> 初始化管理员

### 5.6 安全提示

登录页可以放一条轻量安全说明。

推荐文案：

> 登录后操作将进入审计记录，请使用本人账号访问控制台。

展示位置：

- 登录按钮下方
- 字号 12px
- 使用 secondary 文本色

## 6. 视觉设计方向

### 6.1 整体风格

建议关键词：

- 克制
- 稳定
- 清晰
- 专业
- 有安全感

不建议：

- 大面积蓝紫渐变
- 营销落地页式 hero
- 装饰性图形堆叠
- 太强烈的阴影
- 过度圆角

### 6.2 背景设计

当前背景为空白浅灰，建议升级为“分层浅背景”。

可选方案：

1. 浅灰青背景加细微网格或线性分割
2. 左侧信息区使用淡品牌色背景块
3. 页面底部加弱边界状态栏

建议颜色：

- 页面背景：`#f3f6f8`
- 表面色：`#ffffff`
- 弱背景：`#f8fafc`
- 品牌色：`#0f766e`
- 品牌弱背景：`#e8f3f1`
- 边框：`#e7edf3`

### 6.3 卡片设计

登录卡片建议：

- 宽度 440px
- border-radius 8px
- border 使用弱边框
- shadow 只用轻微层级
- padding 32px

卡片不建议：

- 大圆角
- 强阴影
- 玻璃拟态
- 复杂背景图

### 6.4 字体层级

推荐：

| 元素 | 字号 | 字重 |
| --- | --- | --- |
| 品牌标题 | 32px | 700 |
| 登录标题 | 26px | 700 |
| 页面说明 | 14px | 400 |
| 表单标签 | 14px | 500 |
| 辅助说明 | 12px | 400 |

## 7. 交互规范

### 7.1 表单行为

- 用户名输入框默认聚焦
- 回车提交表单
- 登录中按钮 loading
- 登录失败保留输入内容
- 密码错误不清空用户名
- 登录成功跳转原目标路径或工作台

### 7.2 错误反馈

建议错误反馈分层：

1. 字段错误：用户名或密码为空
2. 卡片错误：账号密码错误、账号禁用
3. 全局错误：网络异常、服务不可用

推荐文案：

- `请输入用户名`
- `请输入密码`
- `登录失败，请检查账号或密码。`
- `当前服务暂不可用，请稍后重试或联系管理员。`

### 7.3 状态反馈

建议展示：

- `API 已连接`
- `Mock 数据源`
- `Production`
- `Demo`

状态展示应跟随 `USE_MOCK` 或后端健康检查结果。

## 8. 前端落地范围

### 8.1 需要改动的文件

建议改动：

- `frontend/src/pages/auth/LoginPage.tsx`
- `frontend/src/pages/auth/SetupAdminPage.tsx`
- `frontend/src/styles/global.css`

可选改动：

- `frontend/src/lib/config.ts`
- `frontend/src/types/models.ts`
- `frontend/src/store/sessionStore.ts`

如果需要显示版本号，可从：

- `package.json`
- 构建环境变量
- 后端健康接口

中选择一种。

### 8.2 建议新增样式类

建议新增：

- `.auth-shell`
- `.auth-layout`
- `.auth-brand-panel`
- `.auth-brand-mark`
- `.auth-feature-grid`
- `.auth-feature-item`
- `.auth-status-row`
- `.auth-card`
- `.auth-card-footer`
- `.auth-security-note`
- `.auth-page-footer`

### 8.3 建议组件拆分

如果登录页和初始化页都要复用同一视觉框架，建议抽一个轻量组件：

- `frontend/src/pages/auth/AuthLayout.tsx`

组件职责：

- 品牌信息区
- 能力标签区
- 系统状态区
- 页面底部信息
- 右侧 children 表单区

这样 `LoginPage` 和 `SetupAdminPage` 可以共享入口体验。

## 9. 推荐首版实现方案

第一版不建议做复杂动效，只做结构和信息补强。

### 9.1 LoginPage 首版内容

左侧信息区：

- AegisOps
- 企业级运维控制台
- 价值描述
- 四个能力点：资产接入、任务追踪、告警闭环、操作审计
- 系统状态：环境、数据源、安全审计

右侧登录区：

- 登录 AegisOps
- 使用授权账号进入控制台
- 用户名
- 密码
- 登录控制台
- 初始化管理员入口
- 安全提示

底部：

- `AegisOps v0.4.0`
- `内部运维系统`
- `请使用授权账号访问`

### 9.2 SetupAdminPage 首版内容

复用同一 AuthLayout。

右侧表单区调整为：

- 初始化 AegisOps
- 创建第一位系统管理员
- 管理员账号
- 显示名称
- 邮箱
- 密码
- 确认密码
- 初始化管理员
- 返回登录

## 10. 验收标准

### 10.1 视觉验收

- 页面不再只有孤立登录卡片
- 周边信息能说明产品定位和系统状态
- 登录表单仍然是第一视觉焦点
- 整体风格与 AppShell、Dashboard 的新版企业风格一致
- 不出现营销化、花哨或过度装饰的视觉

### 10.2 交互验收

- 用户名默认聚焦
- 回车可提交
- loading 状态明确
- 登录失败有可理解提示
- 初始化入口可点击
- 移动端不发生文字溢出

### 10.3 技术验收

- `npm run build` 通过
- 登录逻辑不变
- 初始化逻辑不变
- 不影响路由守卫和会话恢复
- mock 与真实 API 模式下均可显示合理环境状态

## 11. 最终建议

登录页应从“单一表单页”升级为“AegisOps 的可信入口页”。

建议优先采用左右分区布局：

- 左侧承载品牌、定位、能力、安全和环境信息
- 右侧保持简洁登录表单
- 底部提供版本和访问提示

这样既能解决当前页面周边空白的问题，也不会削弱登录效率。对企业级运维产品来说，登录页不需要华丽，但必须可信、有上下文、有边界感。AegisOps 的登录页应该让用户在输入账号之前，就知道自己进入的是一个可审计、可追踪、面向真实运维动作的控制台。
